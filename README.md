> Документация сформирована на основе анализа исходного кода FlexRouter и обсуждения плана подключения вывода (ламп) в домашний кокпит.

## 1. Общее описание

**FLEXROUTER** — самописный «железный» роутер (внешний процессор) для Microsoft Flight Simulator 2004. Программа управляет переменными в памяти симулятора и переменными, предоставляемыми модулем **FSUIPC**, и маршрутизирует сигналы между физическим железом кабины и виртуальным бортом.

### Возможности
- Чтение сигналов с физических устройств (тумблеры, галетники, кнопки, энкодеры, АЗС) и передача их в симулятор
- Вывод состояний из симулятора на физическое железо (лампы, блинкеры, индикаторы) — реализовано для профилей **ARCC** и **F3/L3**
- Точечная (событийная) передача данных: команда уходит только при изменении состояния переменной, а не полным дампом всех выходов

### Поддерживаемое железо

| Устройство | Роль | Связь с ПК |
|---|---|---|
| F3/L3 | ввод + вывод | FTDI D2XX (`ftd2xx.dll`) |
| ARCC | ввод + вывод | стандартный COM-порт (1250000 бод) |
| Джойстики | ввод | DirectX (SlimDX) |
| Клавиатуры | ввод | — |

### Поддерживаемый борт
**ПТ Ту-154М 2.04 beta 1** (Project Tupolev)

> Самолёт имеет собственную сложную логику систем и кастомную сервисную приборную панель, работающую в обход стандартных дефолтных переменных FS2004, поэтому прямое маппинг джойстиков не работает — требуется мост типа FLEXROUTER.

### Минимальные системные требования
- Windows 7
- .NET Framework 4.5
- SlimDX (оболочка для DirectX)

## 2. Архитектура программы

### 2.1 Поток данных

```
FSUIPC / память симулятора (переменные ПТ Ту-154)
            ↕
   маппинг (переменные борта ↔ выходы/входы железа)
            ↕
   очереди событий (_incomingEvents / _outgoingEvents)
            ↕
   драйверы устройств (ArccDevice, F3Device, ...)
            ↕
   железо (COM-порт / FTDI)
```

- **Вывод**: программа читает данные из FSUIPC (состояния ламп Ту-154); при изменении состояния событие ставится в очередь вывода, драйвер устройства конвертирует его в массив байт и отправляет на плату.
- **Ввод**: callback приёма с порта (`SerialPortDataReceived`) считывает события (кнопки, энкодеры) и ставит их во входную очередь.

### 2.2 Ключевые компоненты

| Файл | Назначение |
|---|---|
| `Arcc\ArccDevice.cs` | Драйвер ARCC: подключение COM-порта, приём и отправка |
| `ArccHardwareDataProcessor.cs` | Конвертация событий в байтовые пакеты: `ConvertEventToByteArrayForHardware(ev) → byte[]` |
| `ArccHardwareUnitTest.cs` | Тесты драйвера ARCC |
| `Hardware\F3\F3Device.cs` | Драйвер F3/L3 через FTDI D2XX |
| `Addons\ftd2xx.dll` | Низкоуровневый драйвер FTDI D2XX |

Базовый интерфейс поддержки материнской платы — `IHardwareDevice`.

### 2.3 Механизм вывода (профиль ARCC)
- Фоновый цикл `SendDataLoop` опрашивает очередь вывода с периодом **2 мс**
- `SendData()` извлекает события по одному, конвертирует их процессором данных и пишет в порт (`_port.Write`)
- Полный дамп всех клавиш модуля — метод `Dump()`: кладёт в очередь `DumpEvent` (перед отправкой делается задержка 1 с, иначе дамп может не выполниться — причина неизвестна)
- У каждого модуля идентификатор `MotherboardId`

## 3. Протоколы обмена

### 3.1 ARCC (рабочий для замены на современный контроллер)
- Реализация: стандартный `System.IO.Ports.SerialPort` (не FTDI D2XX)
- Параметры: **1250000 бод, 8 data bits, нет паритета, 1 stop bit, без handshake**
- При подключении — импульс DTR: `DtrEnable = true` → пауза 1 с → `DtrEnable = false`
- Для USB CDC-устройств (Teensy, Arduino) скорость 1250000 — формальный маркер: фактически данные идут со скоростью шины USB (Full Speed, 12 Мбит/с)
- Модель вывода: точечные компактные пакеты на каждое изменившееся состояние (не дамп всех ламп)
- **Структура пакета — определяется** из `ArccHardwareDataProcessor.ConvertEventToByteArrayForHardware` (см. TODO)

### 3.2 F3/L3
- Низкоуровневый драйвер FTDI D2XX (`ftd2xx.dll`) — минимальная задержка (порядка 1–2 мс против ~16 мс у системного COM)
- Драйвер ищет строго идентификаторы чипов FTDI: **замена на Teensy/Arduino невозможна** (у них родной USB, без чипа FTDI)
- Работа с F3/L3 скрыта за библиотекой, написанной автором FlexRouter (простые методы уровня `SetOutput`)

### 3.3 Железо F3/L3 и ARCC (гипотеза, требует подтверждения)
Контроллеры F3/L3 и ARCC конструктивно близки к Arduino: 8-битные AVR-микроконтроллеры Atmel (ATmega64/128/162/32) с собственной прошивкой, кастомные материнские платы с обвязкой под авиационные тумблеры и лампы на 27 В.

## 4. Текущее состояние стенда

### Ввод (работает)
- **MJoy16 × 1** (64 кнопки, 8 осей)
- **Teensy++ 2.0 × 3** (AT90USB1286, USB CDC)
- Подключено: **средний пульт, оверхед, СПУ**

### Вывод (не работает)
- В роутере вывод реализован только через профили ARCC и F3/L3
- Кабина «слепая»: симулятор не зажигает физические лампы, блинкеры, семисегментные индикаторы
- **Задача**: организовать вывод на современном контроллере без переделки FlexRouter

## 5. Задача: вывод ламп

### 5.1 Рассмотренные варианты

| # | Вариант | Плюсы | Минусы |
|---|---|---|---|
| 1 | FTDI-адаптер (FT232RL) → Teensy, профиль ARCC | без изменения кода FlexRouter; дёшево | лишний переходник и провода |
| 2 | Готовая плата с чипом FTDI FT232RL на борту | FlexRouter «узнаёт» её как F3/L3 | редкое железо |
| 3 | Оригинальные платы F3/ARCC с вторичного рынка | zero-code | давно не выпускаются, устаревшая элементная база |
| 4 | MobiFlight / SimHub параллельно (FlexRouter — только на ввод) | без кода, настройка через GUI | нужно проверить, что ПТ Ту-154М выводит состояния ламп в читаемые FSUIPC-офсеты (часть логики скрыта в .gav/.gau) |
| 5 | **Профиль ARCC через стандартный SerialPort** (Teensy/Arduino как CDC COM) | **без изменения FlexRouter; современное железо работает «из коробки»** | нужно расшифровать формат пакетов и написать скетч |

**Выбран вариант 5** (вариант 1 — частный случай: тот же профиль ARCC, но с FTDI-адаптером).

### 5.2 Железо под вывод
- **Arduino Mega 2560** (желательно исполнение Pro — размер со спичечный коробок) или имеющиеся **Teensy++ 2.0**
- 54 цифровых пина: ~10 займут лампы, остальные — резерв на блинкеры и табло оверхеда
- Обе платы корректно работают с формальной скоростью 1250000 (USB CDC)

### 5.3 Подключение ламп через герконовые реле
Обмотки реле **нельзя** подключать напрямую к пинам MCU: 5 В и 20–40 мА на пин, сгорит от перегрузки или обратного тока индукции.

Варианты схем:
1. **Готовый модуль герконовых реле** на 8/16 каналов («Reed Relay Module Arduino»): защитные диоды и транзисторные ключи уже распаяны; пин MCU → управляющий вход модуля.
2. **Сборка своими руками**: герконовые реле **SIP-1A05** (5 В) + драйвер **ULN2003A** (сборка транзисторов Дарлингтона).

Питание ламп (5 В / 12 В / 27 В авиационное) подводится через силовые контакты реле — логика MCU электрически изолирована от силовых цепей.

## 6. Порядок интеграции

1. Подключить Arduino Mega 2560 (или Teensy) к ПК по USB → получить COM-порт (например, COM5)
2. В конфигурации профиля **ARCC** в FlexRouter указать номер COM-порта
3. Залить на плату скетч: постоянный приём с Serial, декодирование команд, `digitalWrite(pin_лампы, HIGH/LOW)`
4. Проверка: срабатывание сигнализации в симуляторе → команда в COM → реле щёлкает → лампа горит

### 6.1 Подключение ESP32-S3 по сети (TCP, без USB-кабеля)

Готовая альтернатива COM: плата ESP32-S3 с прошивкой `Esp32/` (см. `Esp32/README.md`)
ARCC-совместима и умеет тот же протокол через USB-CDC **или TCP** (порт 4001,
включается в веб-морде платы: `/config` → «TCP-транспорт»).

На стороне FlexRouter сетевые ARCC-устройства подключаются через `ArccNetDevice`
(`Hardware/Arcc/ArccNetDevice.cs`): список адресов берётся из файла
**`ArccNetDevices.txt`** рядом с `FlexRouter.exe`:

```
# одна строка - один адрес host:port
192.168.4.1:4001
# flexrouter.local:4001   (mDNS, если в LAN)
```

- Устройство появится в роутере как `Arcc:NET_<host>_<port>` (с суффиксом NET,
  чтобы не пересекаться с USB).
- При недоступности платы FlexRouter не падает: `ArccNetDevice` сам реконнектится
  с backoff 1с → 5с → 15с; дамп при появлении линка делается как обычно.
- Web-морда платы работает и в LAN, и в её собственном AP (см. `Esp32/README.md`).

## 8. Приложение: фрагменты исходного кода (`Arcc\ArccDevice.cs`)

### Подключение

```csharp
private SerialPort _port;

public bool Connect()
{
    if (_port == null)
    {
        _port = new SerialPort
        {
            BaudRate = 1250000,
            PortName = _comPort,
            Handshake = Handshake.None,
            Parity = Parity.None,
            DataBits = 8,
            StopBits = StopBits.One,
            RtsEnable = false
        };
        _port.DataReceived += SerialPortDataReceived;
        // в оригинале отключены все реакции порта, кроме Cts;
        // после считывания буфер нужно чистить (входной и выходной)
    }

    try
    {
        _port.Open();
        _port.DtrEnable = true;
        Thread.Sleep(1000);
        _port.DtrEnable = false;
    }
    catch (Exception)
    {
        return false;
    }

    return true;
}
```

### Приём (ввод)

```csharp
private void SerialPortDataReceived(object sender, SerialDataReceivedEventArgs e)
{
    var bytesToRead = _port.BytesToRead;
    if (bytesToRead == 0) return;

    lock (_incomingEvents)
    {
        // чтение событий от устройства (кнопки, энкодеры, ...)
    }
}
```

### Отправка (вывод)

```csharp
/// Циклическая функция отправки данных устройству
private void SendDataLoop()
{
    while (true)
    {
        if (_quit) return;
        if (_outgoingEvents.Count == 0)
        {
            Thread.Sleep(2);
            continue;
        }
        SendData();
    }
}

/// Отправить накопившиеся события железу
private void SendData()
{
    lock (_outgoingEvents)
    {
        while (_outgoingEvents.Count != 0)
        {
            var ev = _outgoingEvents.Dequeue();
            var outDataBuffer = _arccHardwareDataProcessor.ConvertEventToByteArrayForHardware(ev);
            if (outDataBuffer != null)
                _port.Write(outDataBuffer, 0, outDataBuffer.Length);
            Thread.Sleep(2);
        }
    }
}
```

### Дамп всех клавиш

```csharp
/// <param name="allHardwareInUse">массив содержит упоминание всех модулей, которые нужно сдампить</param>
public void Dump(ControlProcessorHardware[] allHardwareInUse)
{
    // Если не сделать эту задержку, то дамп может не произойти. Почему - не понятно.
    Thread.Sleep(1000);

    var dumpEvents = new ControlEventBase[1];
    var dumpEvent = new DumpEvent { Hardware = allHardwareInUse[0] };
    dumpEvents[0] = dumpEvent;

    PostOutgoingEvents(dumpEvents);
    System.Diagnostics.Debug.Print("Dump: " + MotherboardId);
}
```
